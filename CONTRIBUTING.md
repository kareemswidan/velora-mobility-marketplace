# Contributing

Thank you for taking the time to improve this project. Bug reports, focused fixes, accessibility improvements, test coverage, and documentation corrections are welcome.

## Development workflow

1. Open an issue or discussion before starting a large change.
2. Create a short-lived branch from `main`.
3. Keep each commit focused on one logical change and use an imperative message such as `Add booking conflict test`.
4. Separate refactors from feature work, and do not commit generated artifacts, secrets, or local data.
5. Run the repository's documented tests and production build before opening a pull request.
6. Describe the problem, solution, verification, screenshots when the UI changes, and any migration or deployment impact.

Small, reviewable pull requests are preferred. Existing public history is preserved; fixes should be added through new commits rather than rewriting shared history.
